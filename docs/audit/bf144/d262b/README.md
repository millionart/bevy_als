# BF144-D262b 足目标与锁定旋转的精度生命周期

`source-facts.json` 保留本轮 fresh 读取的 ALS 状态、目标采样、基座、传送、足限位和最终 Rig 输入源码及修复前目标源码，附源身份与既有原生请求、响应和实际帧输入的哈希。此前 `target/bf144/421` 的原始报告仍缺失；本项复用 D262a 新采的七组原生乘法、D279 骨架/Rig 身份和已封存实际帧，不以旧摘要冒充原始报告。

世界目标与世界锁定旋转保留 F64；源移动基座、本地限位前旋转和最终 Rig 旋转分别在 FQuat4f 对应边界降为 F32。上一帧最终及限位前旋转保存在组件空间，重新锁定及传送使用当前组件旋转重建世界值，避免跨帧延长源端已舍入的精度。目标和基座的 Bevy 组件旋转本身仍来自 F32 输入，不声称能恢复输入已经丢失的精度。旋转 Atan、角度系数及世界限位末额外 Normalize 分别留给 D259–D261。

源 `FQuat::FastLerp` 的负点积分支对目标端乘负号，通用 glam 插值对锁定端乘负号；两者表示同一方向，但分量符号不同，最终组件缓存会在下一次重新锁定时被消费。`.484` 封存的第 23 和 172 帧右脚输入均为负点积且锁量为 1；本轮源码事实和对应输入记录见 `source-facts.json`。最终旋转按源顺序混合并归一化，尚未声称全部浮点尾差通过原生校准。

该修复调整公开的 `AlsFootLockFootState` 世界旋转字段类型、重命名组件缓存字段，并增加 `reset_foot_lock_to_target` 和 `refresh_foot_lock` 的组件旋转参数；仓库内调用点与示例已同步，仓库外调用者需要迁移。

已编写世界值保真、组件缓存重锁、基座精度、实际采样与 Rig 输入的 focused 用例。全部静态修复和 Bevy/依赖迁移后，再运行测试、全量图静态审计、公共视觉 Gate，以及逐项移除 F64 世界值和组件 F32 缓存的消融；恢复源码字节、在启动器同 target 重编并重跑最小反例。上述测试、消融和 Gate 均尚未执行。
