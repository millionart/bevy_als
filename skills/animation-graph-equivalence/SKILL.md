# Animation Graph Equivalence

Use this skill for every animation graph asset change in this repository. Its purpose is to retain ALS-Refactored behavior while making the actual Bevy graph readable and auditable.

## Design ablation

After every graph-equivalence design or implementation, run a focused ablation against each newly introduced adapter, field, map schema member, tool stage, or runtime branch. Remove or merge the candidate in a temporary fixture or controlled equivalent path and rerun the source/static/runtime Gate that it exists to protect. Delete it when the required evidence remains unchanged; otherwise retain only the smallest form whose removal produces a concrete failed boundary. Do not preserve an abstraction merely because it might be useful later or appears more general.

## Establish source facts first

Before changing a graph, re-extract the relevant local ALS-Refactored asset facts. Preserve the complete source graph, pins, links, properties, state transitions, clip values, and node positions in the applicable contract or extraction output. Do not use an old summary, a preview SVG, or a public web copy as the implementation source when local data is available.

When a source C++ path reads a settings struct or asset, inspect the effective local settings object and every selected nested subobject for the active branch. Header defaults are only fallbacks: an asset override can reverse a boolean, duration, play rate, curve option, or animated-angle rule. Record both the code branch and the runtime-selected asset values before mapping a target constant or branch.

docs/als-ref-animation-asset-map.md is read-only. Do not alter it.

## Source visual evidence

For every UE authored graph, collect two independent source facts before changing the target:

- First enumerate existing UnrealEditor instances and probe MCP. When the required persistent Editor is already running and MCP responds, open the exact asset directly with `EditorToolset.EditorAppToolset.OpenEditorForAsset`; do not launch a second Editor or use a command-line asset-open script. Use the command-line or non-terminating Unreal Python startup path only when no usable Editor exists or MCP recovery requires it.
- Use MCP as a graph reader before visual fallback: `AssetTools.load_asset`, `BlueprintTools.list_graphs`, `BlueprintTools.get_graph`, and `BlueprintTools.read_graph_dsl`. Record each graph ref and returned read-only DSL in the current evidence directory. Do not call a Blueprint write tool during source inspection.
- An empty `read_graph_dsl`, `find_nodes`, or Slate screenshot is ambiguous. First verify the existing UnrealEditor process, `list_toolsets`, `load_asset`, `list_graphs`/`get_graph`, and Slate `Observe`/`Snapshot`. Restart only when that health check fails. If the Editor is healthy and only one API is empty, record a capability limitation and use the other MCP read-only APIs, including `find_nodes`, `get_node_infos`, and connected-subgraph reads, before completing the missing coverage from the same native extraction. Never treat a healthy empty DSL as evidence that a graph is empty.
- Re-extract the local source asset and use extract_ue_visible_graph_contract.py to preserve the complete visible source graph, including node properties, pins, links, comments, and positions. Native extraction is authoritative for the full contract; the MCP read is an independent live-Editor fact, not a replacement for it.
- Once the graph is open, use Slate Inspector `Observe` and `Snapshot` to find the graph canvas subtree, then call `Screenshot` on that canvas ref. Only a single full-canvas capture or a provably complete, non-overlapping stitched capture may serve as graph-layout evidence. A partial canvas or whole-editor/window screenshot may prove that an asset is open or healthy but is never graph-layout evidence; prioritize MCP content reads when a full capture is unavailable.
- If the direct graph read or canvas capture is unavailable, record the exact MCP tool failure and render the native source contract with render_ue_visible_graph.py. Computer Use is the final fallback and must follow its own skill instructions.

A target-derived manifest is only a target integrity record. It can never serve as source layout evidence or close a visual-equivalence Gate.

Run command-line native extraction alongside the MCP inspection; it must not be used to replace a responsive persistent Editor asset-open path. Do not launch a temporary Editor process whose script requests Editor exit merely to open a graph: that path can tear down `AnimationBlueprintEditor` while it is active. If Slate cannot expose the graph canvas after the direct Blueprint read succeeds, retain the failed canvas-query evidence and use the freshly extracted contract SVG rather than repeatedly restarting the Editor.

## Toolchain

Use the repository tools as one connected evidence chain:

- `run_ue_source_reader.ps1` produces the fresh native extraction.
- `extract_ue_authored_graph_inventory.py` discovers the complete authored closure; run it with `--write` after extraction and `--check` before the Gate.
- `extract_ue_visible_graph_contract.py` records one graph contract. For a recursive closure, first run `extract_ue_visible_graph_contracts.py --write`, then its `--check`, to materialize and verify every discovered graph, FSM, and transition contract from one fresh native payload; `render_ue_visible_graph.py` is the native-contract visual fallback. Recursive contract file names must remain bounded and platform-portable, with the full source graph identity retained in the batch index and contract body rather than encoded in a deep UE-path file name. Its self-test must exercise a deeply nested source graph path.
- `run_ue_visible_animgraph_audit.py --source <native-extraction>` checks a graph map against the freshly generated target NodeSpec. It may use `tools/` as an isolated AssetServer root for audit-only graphs; never stage those graphs under `assets/`. `audit_ue_visible_fsm.py --source <native-extraction>` does the equivalent State Machine topology and state-layout check. Its static transition assertions must use `PropertyName=value`, never an ambiguous bare value; a source `None` marker requirement may use a concrete target-ABI exception only when the map names the target runtime path.
- `run_ue_visible_animgraph_audits.py --index <generated-index> --source <native-extraction>` runs a declared set of source-visible graph maps serially, preserving one fresh-source audit result per entry; use it for a generated recursive transition set after each individual map has been materialized.
- Generate a mixed recursive audit index from the fresh contract index and source maps when a closure contains both AnimGraphs and FSMs. Its runner must dispatch graph maps to `run_ue_visible_animgraph_audit.py` and FSM maps to `audit_ue_visible_fsm.py`; the manifest validator must prove that every recursive inventory entry is contained in that index, including audit-only transition targets under `tools/`.
- Size a manifest command timeout to the declared closure. The authoring validator must keep the timeout bounded and emit a machine-readable failed command result on expiry; it must never abort the whole Gate without a report. Do not shorten a recursive audit by omitting maps merely to fit a default timeout.
- `audit_animation_transform_conversion.py` compares selected raw UE animation tracks with the target glTF keys after the verified coordinate-basis conversion. Use it for every symptom that could originate in a migrated animation transform, and include translation, rotation, scale, key count, and time grid.
- `validate_runtime_graph_asset_boundary.py --assets-root assets --check` rejects audit-only transition graphs, audit directories, and runtime references to them under the AssetServer tree.
- `create_ue_visible_animgraph_map.py` may seed a map only from an actual fresh NodeSpec. Follow it with `annotate_ue_source_node_defaults.py --write` and `--check` for supported source nodes so every unconnected default, asset, sync group, cache name, and binding has a source/target assertion; review any unsupported node manually rather than accepting an incomplete seed. This includes `BlendListByEnum`: its blend-time defaults, enum default, source property binding, and scalar ABI exception must be recorded even when its pose pins are linked.
- `reorder_ue_visible_fsm_serial.py` may normalize only the serialized state and transition order already established by a source map. It must never invent nodes, endpoints, values, or layouts.
- `validate_animgraph_authoring.py`, `validate_animgraph_editor_assets.py`, and `verify_animgraph_node_positions.py` close the manifest, RON integrity, and graph-node layout portions of the Gate.

Every recursive inventory entry must name a Gate that consumes both its source map and `--source` native extraction. A target contract, generated manifest, or a prior audit output cannot substitute for that live-source argument.

UE can regenerate ephemeral `pin_id` values when serializing the same authored graph, and raw-ID sorting can reorder an otherwise identical top-level link list. Preserve raw IDs and extracted link order for native evidence, but use the extractor's semantic canonical hash for freshness: it excludes only volatile `pin_id` and the hash derived from it, and sorts only the top-level semantic link set. It must still compare node GUID/order, pin name/order/direction/type/default/binding, links by endpoint semantics, position, static values, and every other native field. Add a self-test that changes only raw pin IDs or link-list order and passes freshness, alongside a separate semantic-change rejection test; never work around this by accepting stale contracts or disabling fresh native comparison.

The AB_Als root audit must apply the same semantic canonicalization before comparing a fresh native extraction with its committed source contract. It may ignore regenerated `GraphGuid`, `pin_id`, and legacy reader-only CDO fields absent from the current reader, but must reject any graph node, pin semantic, slot name, property, link endpoint, or layout change. Its self-test must exercise both a volatile-only pass and a source-semantic rejection.

When extending source-visible audit tools, add a regression self-test for every UE graph-root variant used by the workflow, including AnimGraph roots, state results, and transition results. Compare generated NodeSpec text with newline normalization only; retain strict content comparison after normalization so host line endings cannot create false failures or conceal an actual graph change.

## Authoring boundary

Keep the source-visible Pose chain, graph split, node order, node positions, and independent control edges visible in the real .animgraph.ron.

- Use an animation context only for a proven same-pose branch whose inherited F32 curve relay is visual noise.
- Curve membership must be discovered from the source/target graph ABI. Do not hard-code a closed Pose + CurveSet + Attributes payload.
- When a source-visible scalar pin is represented by a `LayeredGraphNode` child input, declare its source default on the adapter and make root-default evaluation consume that declared value. A global key alone is not an auditable fallback. The default annotator must reject a missing target default, but must not require a dynamic key when the source pin has no Property Access binding.
- When an outer visible adapter delegates a sequence evaluator or another static authored node to a child runtime graph, source static property assertions must point to that child runtime path. The outer pin mapping still carries source default and binding; do not duplicate or invent a visible outer ABI solely to make a static assertion pass.
- When a project graph captures source curves from lower-snake-case global keys while the source graph uses PascalCase curve pins, preserve both names in the boundary context. Do not silently fall back to zero for a missing behavior-bearing source curve. A focused runtime case must record the source global value and its final ControlRig-bound value for at least one nonzero curve in the affected chain.
- For a source `Layered blend per bone`, retain each visible Blend Pose pin independently and audit the ordered per-layer branch-filter bones, blend weights, mesh-space rotation flag, and root-motion flag. The default annotator must parse and compare the source and target layer arrays rather than emitting an empty property list; skeleton, virtual-bone, or LOD differences require a concrete runtime ABI exception.
- Keep time, events, control inputs, slots, physics contracts, and other independent channels separate unless the runtime boundary proves their semantics are preserved.
- When a source-visible state graph exposes only Pose but a parent runtime transition still needs time, keep the authored graph Pose-only and place a separate hidden runtime adapter behind it. The adapter must derive its output time from the evaluated Pose timestamp or another source-proven runtime value; never restore a visible time pin merely to satisfy the target engine. If a state-label driver is internalized into an FSM node, its edge state must share that node's FSM state storage rather than introduce a competing node-state type.
- Declare every non-Pose root output in the authoring manifest with a concrete reason and source/runtime evidence. Do not remove an ABI just because Unreal does not display it.
- Treat a StateResult or other graph root's lifecycle fields as behavior-bearing authored properties. When the source root resolves a nonempty lifecycle `MemberName` (or only has a fallback `FunctionName`) in StateEntry, StateExit, InitialUpdate, BecomeRelevant, or Update metadata, the source-visible map must set `require_root_property_assertions: true` and provide one `root_property_assertions` entry per resolved function. Each assertion must point to the target graph or the exact runtime implementation that consumes the lifecycle event; a matching string without a focused behavior regression is insufficient.
- The editor's empty Inputs decoration is not an asset input when the graph has no input pins or edges. Do not create fake inputs to hide it.
- Keep audit-only RON, source contracts, source-visible maps, fixtures, and generated transition expressions under `tools/`, `docs/`, or `target/`, never `assets/graphs/`. The runtime asset tree is reserved for files that AssetServer may discover and load.

For non-graph Character Base assets such as PA_Als and CR_Als, use the same source-fact, explicit-boundary, target-space, lifecycle, and real-entry evidence discipline without creating a fake graph representation.

## Control Rig solver parity

When a source Control Rig graph uses an engine solver unit, extract both the authored node contract and the matching local engine implementation before changing the target. Audit every behavior-bearing input and output, including positional solve, primary and secondary axes, secondary-axis roll weight, pole kind and space, stretch policy, blend weight, propagation behavior, and source initialization basis. A target position-only approximation is not equivalent to a source solver that also aligns bone axes or roll.

For a reusable Control Rig function, inspect every live call site as well as the inner solver node. Per-call pins can override an inner node's visible defaults, especially mirrored left/right axes; materialize and test each call-side variant instead of applying one default to all limbs.

Record each solver pin's semantic kind and space separately. A source Location is an absolute point in its declared space, while a Direction is a vector; never reuse `location - origin` as a Location input. Add a nonzero-character-translation regression for every solver that consumes a location-like pole or target, and require the source-derived per-call variants in the static profile audit rather than merely checking that profile fields exist.

For source Forward Solve nodes that write pelvis or limb transforms, derive every target writeback from the current animation input pose, never from a prior post-rig entity Transform. When the target animation system omits a channel on a frame, capture and restore the last verified animation base before the solver; add a multi-frame regression that rejects accumulated local translation, scale, or segment-length drift.

Materialize source-derived axes, units, and fixed solver settings through the repository's offline coordinate/profile generator, then audit the generated target-space values. Runtime code must consume only those target-space values; it must not invoke a source-to-target coordinate bridge.

When source animation code handles teleportation or another state-invalidating movement event, audit both sides of the target chain: source-equivalent detection/emission and the receiver/rebase/reset behavior. Match source thresholds and time windows exactly, add a boundary regression test, and include a visible real-Playground case that records the detection and resulting pose/foot-lock state. Do not assume a receiver component alone covers an absent runtime event producer.

## Required authoring contract

Create or update a manifest under tools/animgraph_authoring/. It must declare the exact graph node sequence, positions, visible edges, root IO, source-evidence hash, non-Pose root-output exceptions, static source/layout/editor checks, and the named runtime/manual Gate.

For every UE-authored graph in the recursive inventory, create a source-visible map checked through run_ue_visible_animgraph_audit.py. The wrapper regenerates the target's current Rust NodeSpec before it invokes audit_ue_visible_animgraph.py; never use a committed or earlier spec JSON as Gate evidence. When the current native extraction is available, every command must pass it with `--source`; the wrapper then rejects a committed contract that differs from the live native graph. The map must cover every source-visible non-comment node exactly once, match title, node order, position, input-pin order, output-pin order, and root IO, account for every source comment group, and reject missing source links, target nodes, source pins, root output position differences, or source static property/value differences that control the target implementation. Every unconnected nonempty source pin default must have an exact `source_default` and `target_default_contains` assertion; every node configuration value that controls the target implementation must have an explicit source/target property assertion. Splitting, collapsing, or hiding a source-visible node is a failure unless the current checklist item explicitly records a source-backed exception and its editor-visible replacement.

When a fresh source node has an `ErrorMsg` containing an experimental warning, its source-visible AnimGraph map must carry the generated `experimental_node_notes` entry that names the exact source node, target node, source warning, and mandatory future recheck action. Before the source-visible Gate, run:

~~~powershell
python tools/annotate_ue_experimental_nodes.py --root . --glob 'tools/animgraph_authoring/*.visible.json' --write
python tools/annotate_ue_experimental_nodes.py --root . --glob 'tools/animgraph_authoring/*.visible.json' --check
~~~

The visible-graph audit rejects a missing, mismatched, or stale note. A stale note means a fresh source extraction no longer reports the warning: re-extract the node and replace the target behavior from the then-current source before removing the note. The note is maintenance tracking, not an exception to source parity.

## Recursive subgraph closure

Build a recursive authored-subgraph inventory before implementation. It must enumerate the top graph, every reachable State Machine, every state graph, every visible transition graph, and every other reachable authored graph. For every entry record the native source graph path, target RON or FSM path, source contract/map, and the Gate command.

Generate the source side of that inventory from the fresh native extraction, then include its canonical hash as `recursive_source_inventory` in the recipe and manifest. Use `extract_ue_authored_graph_inventory.py` with the source export and root graph suffix. `validate_animgraph_authoring.py` compares the discovered source closure against the manifest exactly; it rejects an omitted source graph, an invented source graph, a mismatched source kind, a contract for a different source graph, a target not declared by the manifest, or a Gate that does not explicitly consume the entry's source map.

Before mapping any recursive entry, materialize the whole closure with `extract_ue_visible_graph_contracts.py` from that same fresh native extraction and verify it in read-only mode. Do not manually enumerate only the graph currently being edited: the batch index and its per-entry contracts are the completeness baseline, while each entry still requires its own map and live-source audit.

Treat every inventory entry as an independent source-visible Gate. A parent graph's pass, a runtime pass, a shared hidden runtime graph, or a target-only manifest cannot cover an omitted state graph. The target state RON must retain the source-visible nodes, pin names, links, static values, and positions of that state; a generic wrapper is only permitted behind those visible nodes and does not replace them.

For State Machine entries, use `audit_ue_visible_fsm.py` to compare entry state, state order/labels/graphs/positions, transition order and endpoints. Transition-node coordinates are explicitly outside the target parity contract: retain the source coordinates in the source contract, but do not require a target coordinate, add a sidecar, or modify `bevy_animation_graph` to represent them. This exception applies only to transition-node coordinates; it does not relax state positions, transition topology, transition graph coverage, transition conditions, static values, pins, or links.

An FSM map without transition property assertions must fail by static-property coverage, not be silently accepted as a topology-only map. When every source transition is represented by a shared target runtime profile, the map may use `transition_static_contract_runtime_path` only if that file contains one exact canonical static contract for each source transition and the target dispatch actually consumes the profile's behavior-bearing values such as duration or blend mode. The FSM audit must verify each full source contract independently; a generic shared string or a source-only summary is insufficient.

For every transition, audit both the transition graph and its parent `AnimStateTransitionNode` static properties. `bAutomaticRuleBasedOnSequencePlayerInState`, automatic trigger time, priority, crossfade duration, blend mode, marker requirements, inertialization, and shared-rule settings can control behavior even when the transition graph contains only a `TransitionResult`; a root default alone never proves that a transition has no behavior.

A `TransitionResult` with no upstream visible node can still carry an unconnected pin default and a UE Property Access binding. Do not generate an empty target output for that case. Preserve the source binding and default through a root passthrough/default ABI in the audit-only graph, and require the root pin map to assert both `target_binding` and the exact target default. Add a generator self-test for this zero-node bound-root form before accepting it in a recursive Gate.

UE `Slot` nodes can receive a dynamic montage from source C++ rather than a visible AnimGraph pose pin. Extract the source queue/play/stop code and slot name before implementation. The target must sample the selected runtime graph or sequence, inject a real Pose plus its source-derived weight into the Slot boundary, and prove that the source-visible Slot result changes; setting only scalar index/weight globals is not a montage implementation. When the source sequence is additive, the target Slot must use additive composition rather than linear interpolation, with a focused test that distinguishes a nonzero sampled delta, changed Slot-node output, and changed downstream final pose. If the Slot changes but a later graph discards it, record that exact consumer boundary for its owning checklist item; do not claim end-to-end parity or alter the later module without fresh source facts.

When source dynamic-montage blend-out uses inertialization, inspect the local montage `Stop` and Slot update implementation as well as the visible downstream Inertialization node. Source behavior can stop the Slot immediately and send a duration request to that visible node; do not approximate this with a scalar fade-out. Preserve the source node's reset/forward/filter settings, carry a one-shot runtime request to its actual authored ancestor, and use source-derived pose-history residuals plus velocity decay. The focused Gate must prove all four boundaries: sampled Slot mount changes the authored chain, natural montage completion emits the request, the first stopped frame retains a nonzero inertial residual, and the pose settles to the source base by the requested duration.

If source `Montage_Play` replaces an active montage in the same slot group with a standard blend-out, model the active montage stack rather than resetting one scalar player. Every fading entry must keep its source clip time, blend weight, sampled pose, and behavior-bearing curves until its own blend-out ends; combine non-additive poses by source weights, normalize only when their sum exceeds one, and retain source pose weight otherwise. A newly spawned target sampler must receive its initial global inputs before its first graph evaluation, then receive normal per-frame updates; an expected first-frame asset delay is not a graph error, while a real graph error remains a failure. While the first sampler pose is unavailable, the montage entry must still block same-slot requeue but must not advance clip time, blend-in, curve time, or natural completion; on the first ready pose, evaluate from source time zero. Add a pure readiness-clock ablation that proves removing this gate skips initial behavior-bearing curves, alongside the stack-weight/pose regression and a real-entry repeated-request case.

For a source State Machine transition with an automatic remaining-time rule, preserve the engine trigger semantics rather than only the target player's wrapped time. A looped source Sequence Player can trigger at a loop boundary; a target `rem_euclid` time alone loses that boundary. Carry an explicit cycle-completed event through the runtime transition adapter, audit the source trigger time/crossfade rule, and add a regression where a loop boundary exits the source state while an incomplete cycle does not.

When a source loop flag becomes false, preserve the in-progress sequence's finishing state until its current clip reaches the end; do not clear the finishing flag merely because the source rotate predicate remains false on the next frame. The finishing state must keep source pose/curve time advancing exactly once to the exit boundary, then permit the authored automatic transition. Add a regression that calls the stop path repeatedly before the clip end and proves finishing remains set.

For stationary ViewDirection rotation, extract the source branch before assuming generic view-follow rotation. ALS can hold actor yaw while no movement input is present and let `RotationYawSpeed` drive the turn; preserve the source blocked-state initialization, reset triggers, and current simulation Delta. A real-entry turn case must prove curve-driven rotation, Slot completion, and inertia without overwriting the actor transform from test code.

When a graph writer produces a behavior-bearing current-frame value such as `RotationYawSpeed` for a same-frame movement/rotation consumer, write an already-existing target component directly and schedule the writer after its fresh animation/motion inputs but before the consumer. A deferred insert/update can expose an older curve sample for multiple stages or frames and silently skip a curve prefix. Use deferred insertion only for first-time component creation; after it exists, require direct assignment. Do not impose a cross-stage ordering that creates a scheduler cycle merely to obtain a later physics value; if a source fact genuinely requires two stages, split the producer/consumer boundary with an explicit fresh snapshot at the compatible stage. The runtime trace must show clip time, sampled curve, and actor yaw progressing coherently, and a focused regression must reject a stale previous-frame curve relay.

Comment groups use comment_policy: require by default. Use comment_policy: ignore only after a user-approved active-checklist exception; preserve the source comments in the source contract and record the reason in comment_exception. Ignoring comments never relaxes node, pin, edge, state-machine, cache, or position requirements.

Run the read-only authoring gate:

~~~powershell
python tools/validate_animgraph_authoring.py --manifest <manifest> --check
~~~

Run the mandatory editor-asset repair and read-only verification after every graph edit:

~~~powershell
python tools/validate_animgraph_editor_assets.py --root assets/graphs --fix
python tools/validate_animgraph_editor_assets.py --root assets/graphs
python tools/verify_animgraph_node_positions.py --root assets/graphs --include <graph-or-directory>
~~~

Then run the scope's source audit, focused Rust/contract Gate, and the declared run_manual.bat Playground case. Record source extraction time, static output, runtime values, and real-entry outcome in the current checklist item and commit.

## Reopened work and shared animation semantics

When a previously accepted graph item is reopened, stop implementation and first identify the exact false-positive path: source behavior, target symptom, the previously passing assertion, and the unobserved final-pose boundary. Mark the checklist item incomplete. Do not restore the check until a focused regression makes that original false positive fail.

Use the repository's shared animation-semantic evidence path for every graph behavior that can change a character pose. A scenario declares each source-backed animation window through the common runtime evidence API: a stable label, source node or clip identity, and whether pre-rig local-pose motion is required or source-proven static. The common collector records the window label, source identity, pre-rig local-bone motion across multiple samples, final screenshot, and runtime-state labels; the common validator rejects missing or static dynamic windows.

State/FSM selection, graph input pins, cache resolution, clip identifiers, world translation, final IK movement, image validity, and no graph error are only supporting facts. They cannot prove that a dynamic source sequence reaches the final pre-rig pose. A cached-pose producer/consumer that crosses an authored graph boundary requires an explicit source-to-runtime cache contract and a real-entry motion window for its final consumer.

For a source `Use cached pose` that resolves through a child state graph, preserve the compiler-linked owner scope, not only the visible cache name. The target `SourceCachedPoseSaveNode` and every matching `SourceScopedCachedPoseUseNode` must declare the same deterministic scope key for the exact owner graph; a scan of all live graph contexts for the first equal name is forbidden because linked ALS graphs reuse cache names. The scope key must be plain target metadata rather than a reverse graph-handle dependency, because a child graph depending on its parent creates an AssetServer load cycle. Add a source-contract-backed `validate_scoped_cached_pose_contract.py` specification that covers every source save/use pair and scope key in the changed scope, and make its read-only command part of the authoring manifest before any focused or real runtime Gate.

A final-skeleton anomaly or a downstream ablation that changes the symptom is sensitivity evidence, not root-cause proof. Before changing IK, Control Rig, layering, or another downstream consumer, record the source-authored chain under the same real input: Sequence Player or Evaluator output, cache producer, cache consumer, State Machine state output, parent graph output, then final pose. The first boundary that fails its source dynamic invariant is the only current repair candidate. If an existing focused gate fails because it asserts a stale target architecture, replace it with a minimal current-source chain contract before interpreting any downstream result.

Do not treat a project-side driver, requested state, target transition index, or predicted FSM state as the graph's actual state. For every source State Machine window, read the relevant `InterruptibleFsmState` from the live `AnimationGraphPlayer` context, record actual state, transition-active, and pose-ready separately from the driver request, and require the source-derived settled state. Name telemetry fields `requested_*` and `actual_*`; manual coverage and visual validation may use only `actual_*` to prove state selection. Add a self-test where the driver reports the expected state while the actual parent FSM remains in a different state or transition, and require it to fail.

For a hidden direct-transition adapter, a missing global driver input means no event, never index zero. Verify the source FSM entry state and the relevant source transition's automatic-rule property before choosing an adapter default. An implicit numeric zero can fire the first serialized transition when a linked graph is evaluated before its project writer initializes, poisoning the actual FSM state while the driver later reports a different desired state. Declare `default_value: -1.0` on the target transition driver, audit it statically, and add a regression that rejects a missing-input transition event.

For every source-backed dynamic window, record the root graph Pose output presence, bone count, active channel count, and reference-like samples. A settled dynamic window must reject a reference/A-pose root output, static pre-rig local pose, or static final local pose after Control Rig and IK. Root/world translation, rig-only movement, camera movement, finite transforms, or a nonempty screenshot cannot substitute for those three boundaries.

When a source State Machine has mutually exclusive direction/state branches or independent clips/BlendSpaces, declare each selected source state, the expected target direction and FSM state, the source sync group, and a canonical synchronized phase. Derive each fixture from the same fresh source transition endpoints, predecessor state, property/branch conditions, and numeric thresholds; state labels, graph position, or an intuitive diagonal input do not establish a source trigger. The runtime report must retain the observed direction/FSM state from the same frame and a canonical pre-rig local-pose signature. The validator must require exact source selection and pairwise-distinct signatures for every required member of the group. Target self-consistency, such as a target-computed direction agreeing with a target-selected state, is insufficient.

When extending the shared validator, add self-tests where a state, input, and clip identifier are all correct while the final pre-rig pose remains static; a reference root pose; a static final pose; a wrong source state; and multiple source direction branches collapse to one canonical pose. Each must fail before the affected graph can be reaccepted. Keep the mechanism declarative and reusable: future ALS features add source-backed windows to the common path rather than a separate ad hoc validator.

## Runtime visual and performance evidence

When a source action has distinct left/right, clockwise/counterclockwise, or signed actor-yaw behavior, treat its yaw-speed curve as an algorithmic scalar rather than a skeletal transform. Derive its target sign, unit, and accumulated direction from a same-action local source runtime observation; the target numeric sign may invert with the coordinate basis. Do not route it through a generic skeletal transform or Rotator conversion merely because its name contains yaw: use a dedicated source-heading-to-runtime-heading scalar conversion in the offline generator, with a basis invariant test. Materialize the result in the offline asset generator, then make the generated curve contract compare source turn side and target signed scalar for every affected variant.

Convert an authored scalar curve as a complete interpolated function, not as a list of key values. When the source-to-target value mapping changes sign or units, convert every value-space tangent, derivative, and value offset by the corresponding derivative mapping; preserve time positions, time-axis weights, and interpolation mode only after source semantics prove they are time-space quantities. The source contract must retain all interpolation, tangent, weight, and extrapolation fields. Add a focused test that samples every interval midpoint and proves `target_curve.sample(t)` equals the converted `source_curve.sample(t)`; key equality or an equal integral alone is insufficient.

Scope behavior-bearing curve relay to the source authored state that owns it. A dynamic Slot curve in an Idle state must not be sampled merely because a target turn drive still exists while another Rotate/Move/Stop state is active; likewise a Rotate sequence curve is valid only while its source sequence is active or explicitly finishing. Record the source state-to-curve ownership in the static map and add a regression where an inactive drive outside its owning state cannot produce nonzero actor-yaw speed.

The source owning-state boundary also gates action creation, not only curve relay. If a source Slot and its refresh function live inside an Idle state graph, do not let a target detector accumulate activation delay or start the Slot clock until telemetry proves that exact owner state is active and not transitioning; reset the detector outside that boundary. Otherwise the target can begin a montage while Move/Stop is still resolving, discard its initial curve prefix, and later appear to use the right asset with an incorrect final yaw. Add a focused eligibility test for missing, non-owner, transitioning, and stable-owner states.

Record the ECS owner of every graph-state telemetry component. The animated avatar, graph player, and gameplay character can be different entities; resolve a parent-child owner path explicitly before querying a State/Slot telemetry component. Add a focused world test in which telemetry exists on the character, is absent on the avatar, and only the resolved character lookup enables the source owner-state condition.

For every source-backed state action, record both the target dispatcher-requested parent state/transition and the graph-resolved parent state/transition in the runtime window and trace. If requested is correct but resolved is wrong, diagnose the graph/event handoff; if requested is wrong, diagnose the source input or dispatcher before touching curves, IK, or pose code. The common validator must reject each mismatch independently.

Keep the runtime evidence format identifier in one shared contract file consumed by both the Rust collector and the Python validator. Rust must include the contract at compile time and Python must load the same file; add a Rust contract test and run the validator self-test whenever the schema changes. Do not maintain duplicated version literals that can turn a valid animation run into a schema-only failure.

Every such dynamic window must declare the source-derived expected runtime-space signed actor-yaw direction in addition to its absolute yaw floor. The common report must record the observed signed delta relative to the window baseline, and the validator must reject a branch whose clip/state selection and yaw magnitude look valid but whose target-space signed actor yaw is opposite. Add an independent self-test for that false-positive report before accepting the change.

Report the greatest displacement in both the expected and opposite yaw directions. Classify a branch as opposite only when the opposite excursion is source-significant and dominates the expected-direction excursion; a correct-sign but insufficient displacement must remain a motion/convergence failure rather than being mislabeled as reversal. The validator self-test must separately reject an actual reversed trace and preserve that distinction.

For any curve-driven turn, rotate, or dynamic montage window, retain the per-sample actor yaw, view yaw, curve value, active clip time, and montage/rotate weight in the machine-readable trace. Require finite nonnegative clip time and weight and at least one nonzero curve sample; without those fields, a sampler readiness delay, skipped curve prefix, stale curve, or blend-weight loss cannot be distinguished from a source algorithm mismatch.

For a source action with distinct directional assets, the same trace must declare the expected target animation variant and the actual selected variant for every sampled active clip. The validator must reject any active mismatch independently of yaw magnitude, curve sign, or final pose; this catches a swapped Left/Right selection even when both assets animate plausibly.

For a dynamic Slot or montage, also record every relevant active stack entry on every trace sample: target variant, clip elapsed, weight, play rate, and sampler-ready state. A latest-drive field or total stack weight cannot reveal an old entry blended into a new action or a divergent curve clock. Add a focused test that parses the actual imported target asset, feeds one fully weighted active stack entry at a known clip time, and verifies the composed curve value. If that direct test passes while the real trace differs, diagnose stack lifetime, owner-state relevance, or schedule timing rather than changing source-derived curve keys.

When a single-entry stack still disagrees with the final relay, record both the direct curve sample from the actual runtime-loaded asset handle at that exact clip time and the final relay value. A wrong direct value isolates loader or asset identity; a correct direct value with a wrong relay isolates composition, state scope, or write timing. Never treat these two failures as a reason to alter source-derived key values.

Begin a dynamic-window trace only when its source action is actually active: its owner state/branch is valid, the selected clip or Slot has started, and the source-relevant curve path is live. Precondition frames, residual cleanup, and a view target before action activation may declare the required window but must not establish actor-yaw baseline, state membership, motion span, or convergence. For a source looped Rotate action, the fixture must wait for either the source loop boundary or the natural end of the current sequence after the loop predicate becomes false, then observe the returned stable stationary owner state before marking completion; an active first frame is not completion.

Treat the real Playground run as the final integration backstop for one coherent graph-change batch, never as a step-by-step exploration tool. Before invoking it, complete the fresh local source extraction, source-visible/static graph and FSM contracts, cache-scope and root-handoff audit, focused fixture/unit/self-tests, compilation, and declared manifest/editor checks. A new probe field, report schema member, or tentative diagnosis must be exercised first in an offline fixture or focused test; it does not authorize a real runtime run. If the final runtime Gate fails, return to source facts and static-chain analysis, close the revised static Gate, then perform one new end-to-end run. Do not repeatedly launch `run_manual.bat` after individual edits to learn which incomplete boundary changed.

For every graph change that can affect a visible pose, additive layer, state transition, IK, Control Rig, ragdoll, root motion, or animation asset selection, run the reusable real-Playground visual Gate before declaring equivalence:

~~~powershell
pwsh tools/run_animation_visual_validation.ps1 -Case <manual-case>
python tools/validate_animation_visual_evidence.py --report <evidence-dir>/report.json --check
~~~

The report must be generated by the runtime camera and final post-propagation skeleton, not a mock or editor preview. It must retain multiple scene PNGs, key-bone transform/scale/segment-continuity checks, graph errors, wall-frame plus graph-evaluation p50/p95/max metrics, and the exact automatic scenario/phase/phase elapsed/locomotion/gait/stance/rotation-mode state for every pose and screenshot. A clean process exit or `graph_err=none` is insufficient. Any invalid transform, collapsed or implausibly scaled skeleton, abrupt joint discontinuity, invalid rendered image, missing state label, or performance-budget breach fails the Gate and leaves the offending sample and image in the evidence directory.

Run an engine-agnostic temporal skeleton guard on every final local/global skeleton frame, independently of the active graph, IK/Control Rig implementation, source curve, or project-side algorithm. It must reject non-finite transforms, scale failures, local translation/rotation spikes, segment-length ratio spikes, non-degenerate limb-plane flips, and avatar-relative bone-position spikes; on the first occurrence record the bone or chain, prior/current values, threshold, frame time, scenario labels, and a fault screenshot. The report schema must require an empty `temporal_anomalies` collection for success, and the validator self-test must reject a valid-looking report containing a one-frame leg twist or plane flip. Source-specific solver invariants remain supplemental source-parity checks, never the sole detector for a visible deformation.

Maintain focused temporal-guard fixtures for an isolated one-frame local translation, twist, scale, segment-length, avatar-relative position, and non-degenerate limb-plane flip. Every fixture must make the common guard report the anomaly; removing the required history must make the matching anomaly invisible in a separate ablation test. These are geometry/time checks, not Foot IK or project-algorithm assertions.

Record the temporal guard independently at pre-rig and final stages. A final-only anomaly is evidence for a downstream Control Rig/IK boundary; do not change the source clip or state selection until its earlier source-pose chain has been checked. Rebase temporal history only when the declared phase, direction case, or stance changes, or when a declared dynamic window becomes settled; the first post-rebase frame establishes a baseline and every later frame remains guarded. Never reset history because an actual FSM state, curve, weight, or anomaly would otherwise fail. A fault capture has priority over all same-frame scheduled, direction, or teleport captures.

For a source function invoked from an AnimGraph call node, do not equate the C++ function body with an unconditional target-frame system. Verify the source graph relevance and Slot update path as well: an active Slot can suppress its source-pose update and therefore stop a downstream authored call from re-queuing a dynamic Montage even when the C++ body itself contains no explicit active-montage guard. Pair the C++ extraction with a real source PIE observation whenever a dynamic montage, curve-driven actor rotation, or Slot lifecycle is involved. The target must gate enqueueing at the corresponding source relevance boundary, preserve only the source-visible active montage(s), and add a regression showing that removing the active-Slot guard restarts an in-progress Montage while the guard permits natural completion and inertialization.

When a source action should rotate the actor or execute a Slot lifecycle, declare its dynamic window before the real run. The common window record must require source-derived actual FSM state, source-pose chain, final pose motion, minimum actor-yaw delta and actor-to-view yaw convergence when applicable, and every required lifecycle stage such as Slot active, natural completion, inertialization, and settled recovery. The collector must declare a required window even when it fails to become settled; a missing window, wrong actual state, zero or opposite actor yaw, non-converging view error, or incomplete lifecycle must fail the shared validator rather than being hidden by driver telemetry or a coverage boolean.

Slot, sequence, and inertialization lifecycle signals can last only one render frame. After the producer bridge and on every render frame, register lifecycle metadata for an already active source window independently of any decimated pose, skeleton, trace, or screenshot sample. Keep expensive pose collection decimated when needed, but never make it the only lifecycle observer. Add a focused regression in which a completion pulse occurs strictly between two pose samples and remains in the report; a precondition frame must not register observed lifecycle, actor-yaw baseline, state membership, motion span, or convergence.

If a source completion or settled pulse occurs after the last scheduled pose sample and can end the scenario in that render frame, force a same-frame complete pose/trace sample and report flush. Retaining metadata only in memory or waiting for the periodic report is insufficient. Add a focused regression for that terminal-pulse path. A minimum wall-clock observation interval is valid only when source facts explicitly define it; otherwise use source lifecycle, active clip time, curve, and final state rather than an arbitrary duration to determine action completion.

When a fixture reconstructs or replaces an animation window after generic telemetry has already been filled, immediately reapply one shared trace writer for actor yaw, view yaw, curve, clip time, weight, play rate, stack, and actual variant, and reattach source/actual state separately. Do not selectively restore fields. Add a focused construction regression for every reconstructed Rotate, Turn, or Slot window that proves the final evidence retains the complete trace; the common validator must continue rejecting a missing trace.

A source action's active FSM state can differ from its settled terminal FSM state. Derive both from the source transition endpoint, declare both in the dynamic window, and record requested/actual state separately for each phase. Never mix a terminal Idle or Move sample into the active Rotate or Turn state set, and never discard the terminal state merely to avoid a mismatch. The common validator and its self-test must reject wrong active actual state, wrong active requested state, and wrong terminal state independently.

Derive terminal requested transition activity from the source transition property rather than assuming it is false. A source sequence-player automatic rule can emit a transition request in the same frame that the graph has resolved its terminal state. Assert terminal actual and requested transition activity separately; conflating them either rejects a correct automatic transition or hides a missing request.

If a runtime bridge publishes Slot/FSM/pose-ready telemetry after an animation final stage, every consumer, observer, and Gate that reads that telemetry must explicitly run after the bridge SystemSet. Registration order is not evidence of a same-frame handoff. Add a focused schedule regression that makes a stale pre-bridge lifecycle state differ from the post-bridge state, and require the observation path to report the latter.

For a source scenario whose Control Rig branches on animation curves, the report must also record the source-global curve value and the final curve context at the rig boundary. When the source trace proves a required nonzero value, require the target value explicitly; finite zero or a missing-context fallback is a failure, not a passing default.

When a visual or performance Gate detects an anomaly, first re-extract the matching local ALS-Refactored asset, visible graph, Control Rig, or C++ algorithm and compare it with the target before editing runtime behavior. The report identifies a symptom; it never authorizes an independent optimization, compensation, smoothing change, threshold relaxation, or algorithm rewrite. Change the target only for a source-proven difference; if the source has the same behavior or the difference cannot be proven, preserve the target behavior and record the evidence.

An automatic real-entry phase that claims to cover a source state with a stationary precondition must explicitly establish that precondition: clear commanded movement and residual velocity at the phase boundary before requesting view rotation or a turn. Waiting for a duration after a moving case is not evidence that the character became stationary. Factor the phase predicate into a focused regression so a later fixture edit cannot silently reintroduce stale motion.

When a source branch depends on a mode that is ordinarily driven by user input, drive the source-equivalent input as well as requesting the mode, then assert the resulting live mode in the scenario. Directly writing a state component is insufficient when a later input-state system can restore the mode; for example, an aiming-only Rotate In Place case must hold aim through its rotate window and release it before a View Direction turn case.

After a source-proven fix, retain only the reusable source contract, regression assertion, scenario configuration, and final Gate result required by the active checklist. Do not accumulate redundant failed screenshots, transient reports, or narrative evidence once their diagnostic role is complete; the durable outcome is a test that reproduces and rejects the regression.

Use a committed baseline only when it was captured in an independent verified run. Never create or accept a baseline in the same change being evaluated.

Before diagnosing a visual Gate frame-time failure as animation or simulation cost, extract the local source project's effective frame-pacing configuration, including VSync and frame-rate limits. Match source pacing in the target real entry before comparing wall-frame p50/p95; a target default that halves presentation cadence is a source-proven runtime mismatch, not a reason to relax the Gate threshold or attribute the delay to graph evaluation.

Physics timing must be mapped by executed semantics rather than a matching setting name or numeric value. Extract the local source physics frame path and the target scheduler before translating a maximum Delta, substep limit, or asynchronous flag. Distinguish a synchronous once-per-frame step with a clamped Delta from an accumulator-driven fixed schedule that can execute zero or many steps per render. For the local ALS-Ref Chaos path with `bSubstepping=false`, `MaxPhysicsDeltaTime` clamps one frame's physics Delta to `min(frame_delta, max_delta)`; it is not a fixed-Hz request. Do not map its `1/30` default to `Time<Fixed>::set_timestep(1/30)` or retain any other timing change unless a focused real-entry regression proves matching steps-per-render, state progression, and final visual/performance evidence.

When local source facts prove a synchronous one-step physics path, use the target's supported variable-time schedule so controller/game input runs once in its normal update phase and the physics/animation pre-post chain runs once per render in its physics phase. Apply a source maximum Delta through a project-side adapter only while the target physics systems execute, then restore the normal game/animation clock before downstream graph, pose, or camera systems. Do not globally clamp virtual time to approximate a physics-only source setting. The reusable visual evidence must require one physics step per render and independent `physics`/`physics_step` timing samples, so a scheduling regression cannot be misreported as animation cost.

Do not modify bevy_animation_graph, bevy_animation_graph_editor, or a dependency revision for graph-layout parity. Use project assets, source contracts, maps, and validation tools unless a separate active checklist item authorizes a generic runtime capability change for a behavior that cannot be implemented project-side.

## Explicit scenario temporal rebase

When an automated source fixture deliberately resets an actor transform or physics rotation to establish a separate source-backed branch precondition, increment a declared temporal rebase epoch before the reset. Feed that epoch into the shared temporal guard so it resets both pre-rig and final history before evaluating that same render frame. The epoch must be recorded by the fixture and must never advance from an FSM state, animation weight, curve, IK result, anomaly, or any heuristic. Without it, a discontinuity remains a failure; after it, every following frame remains guarded normally. Add a focused regression for the epoch boundary and preserve the generic one-frame twist, scale, segment, position, and limb-plane fixtures.

At the same explicit fixture reset boundary, clear or reconstruct every transient behavior state whose target, filter history, constraint limit, cached pose, velocity, or lifecycle data was derived from the preceding window. A temporal guard rebase alone does not reinitialize behavior: a stale rotation-response smooth target can immediately overwrite the reset heading and corrupt the next source turn. Add a focused regression that seeds nonzero stale state, performs the reset, and proves the first new source action begins from the reset pose and its own source-derived input.

When a fixture chains source actions with lifecycle dependencies, advance to the next window only from actual source-equivalent completion evidence, such as the required FSM state plus Slot active, natural completion, inertialization, and settled recovery. Never use a preallocated wall-clock slot as proof that the preceding action finished. A duration may impose a failure timeout, but must not silently advance the scenario; add a focused regression where an action becomes active without completing and the scheduler remains on that action.

When a source action is defined by a relative view/actor yaw interval, capture the actual target actor heading at the verified stationary precondition and derive the target view heading from that captured value. Do not reuse a fixed spawn-facing value after real physics, rotation, or lifecycle systems have run: that silently changes the source input interval and contaminates signed-yaw/convergence evidence. Add a fixture regression with a deliberately drifted actor heading.

A fixture reference-frame lock is valid only for the declared source window that needs it. End its transform, physics-rotation, and view-yaw writes at that window boundary before a subsequent Rotate, Turn, Slot, IK, or Control Rig case begins; otherwise the fixture can overwrite the behavior it claims to measure. Add a boundary regression proving the lock is active within its own window and inactive at the next source action.
